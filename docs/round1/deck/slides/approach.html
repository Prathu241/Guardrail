Proposed approach · components

What we build, and with what

ComponentTechnique and tools
AgentLangGraph state machine: agent → verify → await approval → execute. Claude Opus 5.5 as the agent. Tools are never callable directly.
Allowlist checks30 Python checks against a SQLite system of record (orders, customers, products, policies). Limits come from the policy records.
ProvenanceEvery ID, amount and quantity must appear in the user's words or in a tool result the agent actually received.
Model reviewClaude Haiku 5.5 (fast), Opus 5.5 (careful), Sonnet 5.5 (second opinion). JSON output; quoted evidence checked verbatim.
CommitOne BEGIN IMMEDIATE transaction: re-check, write, verify the postcondition. Idempotent per action; runs checkpointed.
InterfacesFastAPI with agent mode and a sidecar API for any agent stack; approval dashboard; CLI; Docker.

Domain for the build: a support desk for an outdoor-gear store (refunds, emails, chat replies with policy quotes, stock changes).

The deterministic layer does most of the work at zero model cost; models are used only for the parts rules cannot judge, such as whether a stated reason is something the customer actually said.
